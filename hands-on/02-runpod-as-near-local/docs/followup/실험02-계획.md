# 실험 02 실행 계획

실험01과 공통 저장소를 사용하지만 workload·결과와 가설 판정은 분리한다. 실행 전 설계 파일·코드·설정 SHA-256을 동결해 결과에 남긴다. 변경은 이유를 기록하고 기존 실패를 보존한다.

1. 실험01 완료 후 같은 GPU/지역에 학습 준비 Pod를 생성한다. 파일시스템·GPU·드라이버·Torch 버전을 기록하고 작은 CUDA 연산을 CPU 기준과 대조한다.
2. seed 11·22·33 각각의 U 무중단120-step를 실행하고 최종 가중치·loss를 보존한다. 같은 seed의 별도 프로세스를 초기화해 73-step 장애 실행을 수행한다. 20·40·60 step checkpoint만 완료 저장되며 73에서 예상 종료86을 확인한다. 한 seed 실패를 다른 seed 성공으로 덮지 않는다.
3. 세 checkpoint와 기준 결과를 로컬로 회수하고 bytes/hash를 확인한다. 이 시점에 학습 준비 Pod를 삭제하고 API 부재를 확인한다. 필요하면 시간 한도 때문에 seed별 Pod로 나누되 변경을 기록한다.
4. 다른 ID의 새 Pod 한 개를 생성한다. 세 seed의 F 전체 복구와 W 가중치 복구를 각각 독립 프로세스로 실행한다. 체크포인트 checksum, 복원한 상태 목록, resume step을 기록한다. F의 재개 batch 경로를 U의60→120과 대조한다.
5. 원격에서 저장한 최종 state와 고정 평가 결과로 U/F/W 파라미터 최대 절대오차와 RMS 오차를 산출한다. loss 곡선과 측정시간을 회수한다. F와 U의 GPU/드라이버 차이가 있으면 함께 표시한다.
6. 모든 공개 결과·학습곡선·소형 checkpoint를 로컬 `records/followup/` 또는 비공개 대형파일 경로에 백업한다. 학습 checkpoint와 최종 가중치 원본은 `private/followup-backups/`에 두어 Git에 대형파일을 넣지 않는다. 공개 manifest에는 파일명·bytes·SHA-256만 남긴다.
7. 최종 Pod와 전용 network volume을 삭제하고 API 조회로 소유 자원0을 확인한다. 별도 watchdog 종료를 확인한다. 공급자 청구는 조회 가능 범위만 기록하고 추정값과 섞지 않는다.

개별 원격 job 최대10분, Pod 최대35분, 전체 추가 실험4시간, 총 추가비용 $8 예약한도를 공통 적용한다. 예상 실험02 10~30분, 실패 여유20분. 유료 GPU를 켜 둔 채 분석하지 않고 결과 회수 후 삭제한다. 부족한 범위는 표본 수와 원인을 명시하고 미실시로 남긴다.

최종 보고서는 ① 기존 결과 ② 준비 지연의 원인 ③ 학습 복구의 성립 조건 ④ 비용과 실패 ⑤ 적용 한계 순서로 발표할 수 있도록 작성한다. 실험 미완료를 완료로 표시하거나 계산 예측을 실측으로 포장하지 않는다.
