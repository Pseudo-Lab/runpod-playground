# 실험 01 설계: 저장 위치와 GPU 작업 준비시간

사전 작성: 2026-10-24. 탐색적 소표본 비교. 원래 H3를 부분적으로 다루며, 원격 원본 다운로드 군은 이번 범위에 포함하지 않는다.

## 질문과 가설

기존 구현은 Python 의존성과 3.09GB 모델을 network volume에서 읽었다. 새 Pod 자체의 기동 외에 이 접근 경로가 준비시간에 얼마나 기여하는가? 의존성만 임시 디스크로 옮기는 것과 모델까지 옮기는 것 중, **복사시간을 포함하고도** 첫 결과를 더 빨리 받는 구성이 있는지 확인한다.

주 가설: 원래 경로 대비 한 대안 이상에서 복사를 포함한 프로세스 시작→첫 결과 시간의 3개 블록별 비율 중앙값이 20% 이상 감소한다. 결과 토큰은 모두 동일해야 한다. 20%는 사전 탐색 기준이며 통계적 유의성 기준이 아니다. 부 가설: 모델의 로컬 복사가 모델 로딩을 줄이더라도 최초 사용에서는 복사 비용 때문에 상쇄될 수 있다.

## 실험군

| 군 | Python 추가 의존성 | 모델 파일 | 새 프로세스 시작 후 수행할 작업 |
|---|---|---|---|
| A | network volume | network volume | import→모델 hash→로드→추론 |
| B | Pod `/tmp` | network volume | 의존성 복사→import→hash→로드→추론 |
| C | Pod `/tmp` | Pod `/tmp` | 의존성·모델 복사→import→hash→로드→추론 |

기본 Torch는 동일 이미지에 설치된 것을 공통 사용한다. 의존성 복사 대상에 Torch를 넣지 않는다. 모든 군에서 모델 SHA-256 검사를 수행해 검증비용을 동일하게 포함한다. 복사는 각 측정에서 새 경로로 수행하며 비용을 제외하지 않는다. 의존성 버전은 기존 transformers 4.57.1, huggingface-hub 0.36.0, safetensors 0.6.2를 사용하고 실제 전체 버전을 저장한다.

## 실험 단위와 통제

- 새 Pod 3개가 블록이다. 블록마다 독립 Python 프로세스 3개에서 A/B/C를 각각 1회 수행한다. 실행 순서 ABC / BCA / CAB. 총 9개 측정이다. 반복 단위는 9개의 독립 호스트가 아니라 **Pod 블록 3개**다.
- GPU 1개, 같은 GPU 종류·지역, 동일 image digest·모델 revision·prompt·BF16·greedy·최대 토큰 수·seed를 사용한다. 기존 `experiment.json`의 모델 설정을 복사해 동결한다.
- 모델과 의존성은 사전 준비한다. 최초 다운로드·설치는 공통 준비비로 별도 계측하며 반복군에서 제거한다. provider 이미지·스토리지·OS 캐시를 강제로 비우지 않는다. 순서 교차로 편향을 줄여도 제거했다고 주장하지 않는다.
- `/tmp`가 network volume과 다른 파일시스템인지 `findmnt`와 디스크 정보로 확인한다. SSD·NVMe라는 물리 종류는 관측 없이 단정하지 않는다.
- SSH까지의 기동시간은 Pod별 공통값으로 별도 제시한다. 각 군을 각각 새 Pod에서 시험한 end-to-end 수치로 오인하지 않는다.

## 측정과 분석

동일 원격 monotonic clock으로 복사·import·hash·모델 로드·추론·전체시간을 잰다. 부모 프로세스가 자식 시작부터 결과 완료까지를 재므로 import 이전 비용도 포함한다. CUDA 구간은 synchronize한다. 모델 bytes·hash·출력 토큰·실제 GPU/드라이버·최대 VRAM·라이브러리 버전을 저장한다. 로컬 제어기는 명령 왕복시간과 Pod 수명도 별도 기록한다.

블록별 B/A·C/A·C/B를 계산하고 원자료 3개, 중앙값, 최소·최대를 보여준다. 사전 기준을 만족하지 않으면 개선 실패 또는 혼재로 보고한다. 캐시된 같은 Pod 안에서의 로컬 파일 반복 사용 이익은 복사비용/(직접읽기−로컬읽기)라는 **계산 예측**으로만 제시하며 실측 정책 결과라고 하지 않는다. 분모≤0이면 유한 손익분기를 제시하지 않는다.

## 실패·제약

OOM·비정상 logits·hash 불일치·토큰 불일치는 실패다. 실패 시간·비용도 남긴다. 재고 부족으로 GPU/지역 변경이 필요하면 진행한 블록과 합치지 않고 별도 층으로 남긴다. 변경 후 완전한 3블록을 확보할 예산이 없으면 불완전 결과로 보고한다. 3블록으로 p95나 일반적 신뢰구간을 추정하지 않는다. 이 비교는 컨테이너 이미지에 패키지를 넣은 구성이나 원격 다운로드와의 비교가 아니다.
