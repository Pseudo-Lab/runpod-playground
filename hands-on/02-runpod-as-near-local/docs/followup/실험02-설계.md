# 실험 02 설계: 학습을 중단하고 새 GPU Pod에서 이어갈 수 있는가

사전 작성: 2026-10-24. 기존 H4의 미실시 학습 복구를 작은 통제 작업으로 확장한다. 대형 LLM fine-tuning 성능 실험이 아니라 체크포인트 복구 메커니즘 실험이다.

## 질문과 가설

Pod를 폐기해도 학습 궤적을 복원할 수 있는가? 모델 가중치만 저장하면 충분한가? 전체 상태를 복원한 결과를 무중단 기준선과 비교하고, 가중치만 복원한 군은 반례 후보로 둔다.

주 가설: seed 3개 모두에서 전체 복구군의 최종 파라미터 최대 절대오차≤1e-5, 고정 평가 loss 절대오차≤1e-5, 재개 후 batch 순서 일치를 만족한다. 가중치만 복구군이 다를 것이라는 부 가설은 차이의 방향이나 성능 저하를 보장하지 않는다. 결과가 좋아져도 같은 궤적 재현에 성공한 것으로 보지 않는다.

## 워크로드

- 자체 정의 작은 causal Transformer: vocabulary 128, sequence 64, hidden 128, 2층, 4 heads, feedforward 256, dropout 0.1, batch 8. FP32, AdamW(lr=0.001, weight_decay=0.01), 120 optimizer step, 선형 learning-rate decay.
- 공개 다운로드 데이터 없이 고정 seed로 만든 반복 패턴의 합성 next-token 데이터. 모델의 일반 언어 능력이나 실제 과제 품질을 주장하지 않는다.
- seed 11·22·33을 독립 블록으로 한다. CPU minibatch generator와 CUDA dropout RNG를 분리해 저장한다. 평가셋은 별도 고정 generator로 생성한다.
- 동일 GPU 종류·이미지·실제 Torch 버전, TF32 off, deterministic algorithms, 가능한 math attention 경로로 통제한다. deterministic 설정은 서로 다른 GPU/드라이버 간 bitwise 동일성 보장이 아니다.

## 군과 장애 주입

| 군 | 시작과 종료 | 저장·복원 상태 |
|---|---|---|
| U 무중단 | 0→120 | 기준 결과·최종 가중치 저장 |
| F 전체 복구 | 0→73에서 프로세스 강제 종료, Pod 삭제, 새 Pod에서60→120 | 가중치·optimizer·scheduler·step·CPU/CUDA RNG·batch generator 상태 |
| W 가중치만 | 같은60-step checkpoint에서 새 프로세스로 나머지60 step | 가중치만; optimizer·scheduler·RNG·batch generator 초기화 |

F의 저장 주기는20 step이다. 60-step 완료 checkpoint를 manifest와 함께 확정하고 73-step 계산 후 `os._exit(86)`으로 종료해 finally 기반 추가 저장을 건너뛴다. 로컬 제어기가 실제 종료코드·fault marker를 확인한 뒤 Pod 자체를 삭제한다. 해당 Pod와 다른 ID의 새 Pod에서 F/W를 실행한다. 이는 제어된 프로세스 중단+Pod 삭제이며 provider 강제 장애가 아니다.

W는 '가중치 외 상태 전체 누락'을 묶어 바꾸므로 optimizer 하나의 인과 효과로 해석하지 않는다. W도 동일한 총 optimizer update 수로 비교하되 scheduler와 데이터 순서가 달라진 사실을 명시한다.

## 측정·검증

매 step의 loss·lr·batch hash·시간을 저장하고, 최종 고정 평가 loss·파라미터 오차·RNG/batch 경로·peak VRAM을 비교한다. F의 손실 13 step은 마지막73−완료checkpoint60으로 정의하며 실제 다시 계산한60→73 구간도 로그에 남긴다. 저장시간·checkpoint bytes·로드시간·새 Pod 요청→복구 결과까지 시간을 분리한다. 초기 설정·성능 예열은 학습시간과 구분한다.

checkpoint는 임시 파일에 쓰고 SHA-256·bytes가 든 완료 manifest를 마지막에 쓴다. 새 Pod는 hash 검증 후에만 역직렬화한다. checkpoint는 실험이 직접 생성한 파일만 신뢰하며 외부 pickle을 로드하지 않는다. 로컬 백업도 동일 hash로 검증한 뒤 저장소를 삭제한다.

세 seed별 U/F/W 전체 loss 곡선과 최종 오차를 모두 제시한다. 평균만 제시하거나 차이가 작은 seed를 제외하지 않는다. 성공률은3/3이라는 관측으로만 표현한다. 다른 모델·혼합정밀도·분산학습·실서비스 장애로 일반화하지 않는다.
