# GPU의 투기적 보존과 반납: 실험 설계 및 실행 계획

2026-10-24 사전 설계. 기존 실험을 덮어쓰지 않는다. 새 코드와 이 문서의 SHA-256을 실행 전에 보존한다.

## 질문과 용어

요청을 마친 GPU를 곧 재사용하리라 예상해 유지하는 것을 **투기적 보존**, 당분간 요청이 없으리라 예상해 반납하는 것을 **투기적 반납**이라 부른다. 실제 동작은 RunPod의 Pod 삭제이며, 파일이 저장된 network volume은 유지한다. 영구 데이터 삭제나 실행 중인 요청 취소는 아니다. 예측은 미래 정답을 안다는 뜻이 아니다.

캐시와 공유하는 질문은 미래 재사용의 가치와 보존비용의 비교다. CPU 캐시의 하드웨어 동작, Redis의 TTL·용량 압박에 따른 eviction, LLM의 KV prefix cache가 같은 정책이라는 뜻은 아니다. GPU에는 분당 비용 외에도 할당 실패와 기동 지연이 있다.

## 실제 GPU 실험

RTX5090 EU-RO-1을 우선 사용한다. 생성 시 실시간 견적을 확인하며 기존 5090 기준 $1.19/h 이하 GPU만 사용한다. 기존 이미지·Qwen2.5-1.5B-Instruct revision·BF16·batch 1·greedy 입력을 유지한다. 동시 GPU 최대 1개, 별도 예산 $3, Pod 최대 8분, 전체 2시간 만료와 독립 watchdog을 둔다. 20GB network volume에 준비물을 보관한다. 결과를 회수한 뒤 GPU와 volume 모두 삭제한다.

모델을 GPU 메모리에 상주시킨 작은 단일 요청 worker를 사용한다. 각 정책의 첫 Pod는 준비 완료 상태에서 시작한다. 공통 최초 준비시간과 비용은 별도 보고하며 전체 실험비에는 포함한다. 이후 TTL 만료 시 실제 Pod를 삭제하고 다음 요청에 새 Pod와 worker를 만든다. 프로세스만 재시작하는 모의 실험으로 대체하지 않는다. 출력 토큰과 전체 모델 파일 hash를 기존 결과와 대조한다.

정책 네 가지:

- **상시 보존:** 관측 구간 내내 유지한다. 지연의 참고점이다.
- **즉시 반납:** 대기열이 비면 삭제한다. 기동 중 쌓인 요청은 처리 후 삭제한다.
- **고정 TTL 20초:** 마지막 응답 회수 후 대기열이 빈 상태로 20초 지나면 삭제한다.
- **예측 TTL:** 과거 도착 간격의 EWMA를 갱신한다. 초기값 10초, alpha=0.5, TTL=min(60,max(5,4×EWMA))초. 미래 요청 목록이나 실제 다음 간격은 정책에 주지 않는다. 대기열이 빈 경우에만 마지막 응답 이후 TTL을 적용한다.

합성 도착 시각은 0, 8, 16, 46, 54, 62, 132, 140, 148초. 단순한 요청 군집, 중간 공백, 긴 공백과 종료 후 꼬리를 포함한다. 관측 종료는 175초이며 미완료 요청은 모두 처리한다. 정책 종료 때 남은 Pod도 삭제한다. 이 trace는 실제 사용자 사용기록이 아니며 정책 설계 때 고정한 설명용 작업 부하다. 초기값과 정책계수를 이 trace의 결과를 보고 조정하지 않는다.

난수 seed 20261024로 정책 순서를 한 번 섞고, 정책당 한 번 실제 실행한다. 반복수가 작고 시간대·물리 호스트·공급자 캐시는 통제하지 못하므로 통계적 우월성을 주장하지 않는다. 완전한 서비스 부하 시험도 아니다. 고정 도착시각을 기준으로 응답 대기시간을 재며, 기동 중 도착한 요청도 버리지 않고 FIFO로 처리한다. 로컬 제어기의 SSH·폴링·API 지연도 응답시간에 포함한다.

주요 지표는 정책 구간의 GPU 할당시간·견적 기반 비용, 요청별 응답시간과 최대값, 재할당 횟수, 대기열과 상태 전환 기록이다. p95 같은 모집단 꼬리 지연은 소표본에서 주장하지 않는다. 메모리 캐시 hit ratio만으로 승자를 정하지 않고 비용과 지연을 함께 제시한다. 175초 끝을 미리 아는 것은 실험 종료 처리에만 사용한다.

## 실측값으로 보정한 별도 재생

실제 실행에서 측정한 재기동시간과 상주 worker의 요청시간을 이용해 별도의 이산사건 재생을 수행한다. 재생은 실제 GPU 실험과 분리해 표기한다. 실제와 같은 trace의 적합 여부를 점검하고, 짧은 군집·희박한 요청·교대 패턴·예측이 빗나가는 패턴을 고정 seed로 생성한다. 결과는 해당 모델과 합성 요청분포에만 해당한다. 새로운 실제 사용자 트래픽이나 수백 회 실제 Pod 생성처럼 서술하지 않는다.

향후 요청을 미리 아는 참고 정책을 쓰더라도 실현 가능한 정책과 분리하고, 온라인 정책의 성과로 섞지 않는다. 보존의 오판은 쓴 유휴시간, 반납의 오판은 요청이 지불한 재기동 대기시간으로 설명한다. 하나의 금액으로 합치려면 사용자의 기다림 가치가 필요하므로 임의의 시간 가치를 몰래 넣지 않는다.

## 실패 처리

재할당이 실패하면 원자료와 실패를 남기고 유료 자원을 정리한다. 실패한 trace를 성공 사례로 대체하지 않는다. 코드 변경이 필요하면 최초 소스 hash, 오류와 변경 후 hash를 모두 남긴다. 추정 비용은 확정 청구서와 구분한다.
