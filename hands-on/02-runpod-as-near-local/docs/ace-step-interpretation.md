# ACE-Step 계측을 읽을 때

실험 설계와 모델·코드 고정은 `ace-step-experiment.md`와 `records/ace-step/preregistered.json`에 있다. 이 문서는 실행을 해석하기 위한 보충 노트다. 사전 정책의 매개변수를 바꾸지 않는다.

## 어떤 시계를 쟀나

로컬 제어기의 요청 시작부터 실제 원본 FLAC 회수·hash 검증까지를 전체시간으로 삼았다. 원격 worker의 import, 가중치 hash, DiT 초기화, LM 초기화, 음악 생성은 원격 단조 시계의 구간 시간이다. 서로 다른 호스트의 절대 시각을 빼지 않는다. 생성만 잰 값에는 새 Pod 할당과 파일 전송이 들어 있지 않다.

첫 준비의 전체시간은 제어기가 최초 Pod 생성을 시작하기 직전부터 잰다. 사전 문서의 ‘최초 생성 요청’은 이 자원 생성 흐름을 뜻하며, 모델이 준비된 뒤 음악 생성 API만 호출한 시점이 아니다. 코드의 `prepare()`에서 연속 시계의 시작 위치를 확인할 수 있다.

매번 사용 가중치 약 14.7GB의 전체 hash를 읽는 비용도 포함했다. 최고 속도만 재려는 서비스 벤치마크와 다르다. 기본 모델 저장소의 사용하지 않는 1.7B LM은 다운로드·보관 총량에 포함됐으며, 생성 시에는 4B LM을 썼다. 파일 크기, 파라미터 수와 VRAM 할당량도 구분한다.

## allocator의 옛 snapshot

`records/ace-step/frozen-config.json`은 기존 자원 할당 helper를 재사용하기 위해 복사한 allocator 입력 snapshot이다. helper가 실제 읽는 것은 `image` 필드이며, 그 파일의 과거 Qwen 추론 필드로 ACE-Step을 실행하지 않았다. 실제 ACE-Step 모델·prompt·duration·seed와 backend는 사전 hash를 남긴 `scripts/ace_worker.py`의 API 인자에 고정돼 있다. 결과 보고서는 이 실제 호출과 worker 관측을 사용한다. 옛 snapshot을 사후에 덮어쓰지 않고 범위를 명시한다.

## seed와 재현

공개 API의 seed 42와 Python·NumPy·부모 PyTorch RNG 초기화를 사용했다. 분산 LM backend 내부의 모든 난수 상태까지 완전히 통제했다고 가정하지 않는다. 따라서 같은 모델·입력·seed와 같은 PCM 출력은 서로 다른 검증 항목이다. 파일의 유효성과 PCM hash·RMSE를 따로 보존한다. 차이가 나온 이유를 특정 GPU 커널이나 내부 RNG 하나의 인과효과라고 결론 내리지 않는다.

음원 sample이 유한하고 길이와 채널 수, RMS가 정상이라는 검증은 예술적 품질을 평가한 블라인드 청취시험이 아니다. 감상용 MP3 변환본과 계측·검증에 사용한 원본 FLAC도 구분한다.

## 정책과 가격

음악 실험은 응답 회수 후 같은 시간만큼 쉬는 closed-loop 합성 세션이다. 같은 시각에 도착하는 이전 Qwen trace와 다르다. 각 정책의 요청시각은 달라지며 초기 모델 준비는 정책 비교에서 공통 제외하고 전체비용에는 포함했다. 이후의 재할당과 초기화에는 시간과 비용이 모두 든다.

보유 근사시간은 생성 요청부터 삭제 확인까지의 제어기 구간이다. API 견적과 상태 확인 지연을 포함하므로 공급자의 정확한 과금시간보다 클 수 있다. 전체 자원비용은 별도 자원 ledger의 수명과 단가로 추정한다. 세금·에이전트 비용과 확정 청구를 구분하며, 볼륨의 시간 단위 과금과 연속시간 환산 차이가 있을 수 있다.
