# 글의 주장 보강을 위한 추가 실험

사전 설계: 2026-10-24. 기존 결과는 보존한다. 실험 전에 이 문서와 코드의 SHA-256을 기록한다.

검증 질문은 'RunPod에서 준비물을 남기고 GPU만 삭제하면 새 GPU에서 첫 유효 결과까지 얼마나 걸리는가'다. 선호 GPU는 실제 RTX5090, 지역은EU-RO-1, On-demand 견적$1.19/h다. 생성 직전 재조회하며 이번5090 기준 상한을 넘지 않는다. 활성 GPU 최대1개, 추가 예산$6, Pod 수명30분, volume 전체4시간 제한과 독립watchdog을 둔다.

## 수행

1. 전용20GB network volume에 Pod가 없는 상태에서 S3로 표식 파일을 쓰고 읽어 hash를 확인한다.
2. 최초 Pod에서 고정 의존성을 설치하고 단일 tar 아카이브로 묶는다. 이 일회성 설치·패키징 시간은 별도 기록하며 최초 요청→첫 결과 시간과 비용에 포함한다. 작은 파일 수천 개를 복사했던 기존 방식과 달리 아카이브를 읽고 /tmp에 푸는 방식이다.
3. 첫 실행에서 고정 Qwen2.5-1.5B-Instruct revision의 모델을 빈 volume으로 다운로드한다. BF16·batch1·같은입력·greedy128토큰상한으로 결과를 만든다. 실제 출력 길이와 hash를 기록한다.
4. 결과를 로컬로 회수하고 Pod를 삭제한다. Pod0개 상태에서 S3 표식 왕복과 모델 객체 HEAD 및64KB Range hash를 확인한다.
5. 같은 GPU·지역의 새 Pod3개를 순차 생성한다. 각 Pod에서 의존성 아카이브를 새 /tmp에 풀고 volume의 모델을 offline 모드로 읽어 같은 추론을 수행한다. 요청→SSH, 전개, import, hash, 모델 로드, 추론, 요청→결과회수를 구분한다. 모델 hash·생성토큰은 최초 결과와 대조한다.
6. 매회 Pod 삭제를 확인하고 마지막에는 volume까지 삭제한다. 원본 JSON과로그를 남긴다.

최초 준비1회와 준비물 재사용3회다. 같은 조건의 cold/warm 무작위 인과 실험이나 GPU 성능 대결은 아니다. 최초 설치·모델다운로드·환경구성이 다른 사용 시나리오의 관측이다. 사전 일반화 기준이나p95를 설정하지 않고 원자료3개와중앙값을 보고한다. 빨라지지 않거나 실패하면 그대로 남긴다. archive생성비를 반복측정에서 숨기지 않고 공통일회성준비비로 따로 제시한다.

원래 디렉터리 복사 실험은 L4였고 이번5090과하드웨어·실행흐름도다르므로 차이를tar하나의인과효과로주장하지않는다. 로컬GPU와의동일성능대결,대형모델다운로드시간,실제개발세션유휴율,Codex/Claude모델·effort별대기시간은미측정이다.
