# 5090은 안 샀습니다 — 빌린 GPU로 음악 만들기

본편 35장, 부록 7장. 본편의 장별 설명시간 합계는 약 38분이다. 청중이 이전 실험이나 대화 내용을 안다고 가정하지 않는다. 음원은 HTML에 포함하며, 발표 때 10~20초만 들려줘도 된다.

1. **1–6장 / 약 6분:** 내가 GPU를 사면 얼마나 쓸까. 1,200만원과 99%는 개인적인 가정이다. 임대도 할당시간에 돈을 내므로 작업·파일·GPU 수명을 나눈 실제 실행 흐름을 소개한다.
2. **7–9장 / 약 3분:** 할 일은 ACE-Step 1.5로 60초 음악 만들기다. 실제 음원을 들려주고 최초 준비·새 Pod·상주 반복·정책 비교를 합친 23회 실행의 구성을 보여준다.
3. **10–15장 / 약 7분:** SSH 접속, 모델 준비, 음원 회수를 구분한다. 첫 준비 12분과 재사용 약 3분, 상주 생성 약 7초를 각각 설명한다. 새 Pod 한 번의 import·hash·초기화 내역과 같은 Pod에서 이어 만든 실제 순서를 보여준다.
4. **16–22장 / 약 7분:** 내 작업 흐름에서 감수할 기다림을 묻는다. 파일 캐시와 GPU 메모리를 나누고 Ceph·RADOS를 비교 예로 설명한다. RunPod S3는 network volume 접근 API이며, 실제 Pod 0개 접근과 새 Pod 재사용을 확인했다. 60GB 보관비와 월 사용 가정을 계산한다.
5. **23–28장 / 약 7분:** 투기적 보존·반납의 오판을 설명한다. 24장에 실제 예측 규칙과 10→7.5→16.25초의 계산 예를 넣었다. 30분 사용 여부 규칙은 설명용이며 이번 수치의 정책이 아니다. 25장은 20초 뒤 껐는데 25초 뒤 다시 필요해진 실제 사례, 26장은 네 정책의 비교, 27장은 응답 이후 같은 시간만큼 쉬는 요청 방식이다. 28장에서 재기동도 임대시간이라는 결과를 짚는다.
6. **29–32장 / 약 5분:** 다른 L4 텍스트 작업에서는 반납이 40.5% 절약과 32.7% 지연 증가를 함께 가져왔다. 작업별 답이 다르다는 점과, import를 줄이려고 복사했다가 전체가 늦어진 실패를 설명한다. 그 결과로 고른 개인적 사용 원칙을 제시한다.
7. **33–35장 / 약 3분:** 이런 관리가 귀찮다면 사는 편의성에도 값어치가 있다는 반론을 받는다. 나는 가끔 쓰므로 감수할 만했다는 판단, 결과·자원 정리, 돈이 없었다는 농담으로 마무리한다.

## 질의응답용 부록

36장 ACE-Step 실행 조건, 37장 Qwen 예비 결과의 조건 차이, 38장 L4 유지·삭제 상세, 39장 저장 위치별 9회, 40장 동일 seed의 음원 재현 관측, 41장 전체 상태 전환 시간선, 42장 출처다. 본편만으로 이야기가 완결되며, 부록은 추가 근거를 요청받을 때 사용한다.

## 예상 질문

- **왜 최초 준비가 길었나?** 설치·소스 전송과 전개·import·가중치 검증·초기화·생성·파일 회수까지 실제로 포함했다. 빠른 생성 구간만으로 전체 대기를 대표하지 않는다.
- **이게 가장 빠른 ACE-Step 구성인가?** 아니다. 공식 lockfile과 고정 모델을 사용하고 Flash Attention·torch.compile을 끈 구성이다. 실제 선택된 LM backend와 환경을 기록했다. 최적화 전후의 단일 요인 비교는 하지 않았다.
- **같은 seed면 같은 음악인가?** 이 설정에서 관측한 파일·PCM hash와 차이를 따로 보고한다. 파일의 유효성과 bitwise 재현, 음악의 품질은 다른 기준이다.
- **어떤 정책이 최적인가?** 각 한 세션으로 통계적 우월성을 주장하지 않는다. 미래 요청을 주지 않은 단순 휴리스틱이며 비용과 지연을 함께 본다. 가장 긴 공백은 3분이다.
- **월 계산은 실제 청구인가?** GPU 할당 7.2시간과 60GB 한 달 보관을 가정한 두 항목 계산이다. 실제 월간 사용이나 구매와 임대의 TCO 손익분기가 아니다.
- **로컬 GPU보다 빠르거나 싼가?** 같은 조건의 로컬 성능과 전기료·감가·재판매가를 포함한 비교는 하지 않았다. 내 취미 작업을 임대로 끝낼 수 있었는지 확인한 기록이다.

방향키·Space로 이동, G 목차, N 현재 창 노트, P 발표자 창, B 화면 가리기. 음원은 사용자가 직접 재생하며 다른 장으로 이동하면 멈춘다.
