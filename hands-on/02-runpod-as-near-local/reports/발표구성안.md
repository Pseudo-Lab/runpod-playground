## 발표에서 구분해야 할 것

- 기존 실험의 RTX3090과 L4 결과를 하나의 GPU 성능 평균으로 합치지 않는다. 추가 실험도 날짜와 조건이 다르므로 기존 수치와의 차이를 개선 효과로 직접 주장하지 않는다.
- 실험01의 A/B/C 전체시간은 각 새 프로세스의 복사·import·검증·로드·추론이다. GPU Pod 자체 기동은 공통 단계로 분리한다.
- 저장 위치를 바꿨는데 더 느리게 나오면 복사비용이라는 결과다. 원하는 개선율을 만들기 위해 복사시간을 빼지 않는다.
- 실험02는30만 파라미터 수준의 작은 합성 학습이다.1.5B 모델 전체를 fine-tuning한 실험으로 소개하지 않는다.
- 가중치만 복구해 평가 loss가 좋아져도 전체 상태를 재현했다는 뜻은 아니다. 같은 궤적과 더 좋은 점수는 다른 평가 기준이다.
-13 step 유실은 이번 주기와 장애 시점에서 실제 관측한 양이다. 모든 장애에서13 step만 잃는다는 보장은 아니다.
- 공급자 확정 청구, 로컬 수명×단가 추정, 계정 잔액 감소를 구분한다. 실제 실패와 초기 준비비도 함께 제시한다.

## 예상 질문과 답변 방향

**Q. 그냥 서버리스나 저렴한 로컬 GPU를 쓰면 되지 않나?**  
이번에는 필요할 때 일반 Pod를 할당하는 흐름을 검증했다. 서버리스·로컬 장비의 총소유비용과 비교하지 않았으므로 우열을 결론낼 수 없다.

**Q. 왜 반복이3개뿐인가?**  
적은 비용으로 원인과 메커니즘을 확인하는 탐색 실험이다. 각 측정과 실패를 공개하되 꼬리 지연·일반적 성공률을 주장하지 않는다. 운영 채택 전에는 실제 trace와 더 많은 호스트가 필요하다.

**Q. 가중치 외에 무엇이 필요한가?**  
이번 구현은 optimizer·scheduler·진행 step·CPU/CUDA RNG·batch generator까지 저장했다. AMP·분산학습이라면 scaler·sampler·각 rank 상태 등을 추가로 설계해야 하며 이번 범위에서 검증하지 않았다.

**Q. Network volume이 있으니 백업은 필요 없나?**  
volume은 Pod와 독립된 저장소지만 독립 백업과 동일하지 않다. 이번에는 중요한 checkpoint와 기준 상태를 로컬로 회수하고 hash를 검증한 뒤 유료 저장소를 삭제했다.

**Q. 다음으로 무엇을 하겠나?**  
실험01에서 확인한 준비비용을 고정한 뒤, 조정에 사용하지 않은 실제 요청 trace에서 임계시간 혼합 정책을 비교한다. 학습 복구는 개별 상태 누락·더 큰 작업·여러 checkpoint 주기로 확장할 수 있다. 이번에 이미 검증한 결과와 후속 제안을 구분한다.
